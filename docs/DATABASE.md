# 데이터베이스

Supabase Auth의 `auth.users`가 사용자 ID의 기준입니다. 애플리케이션 테이블은 마이그레이션으로 생성합니다.

| 데이터 | 테이블과 관계 |
| --- | --- |
| 사용자 | `profiles`: 닉네임·일일 목표·알림 설정 |
| 자격증과 공부·독서 | `certifications` → `activities`(과목 또는 도서) → `activity_journal`. 활동 종류별 필드 제약과 소유자 포함 외래키 |
| 집중 | `focus_sessions`: 활동 연결, 시작·활성 구간·누적 시간·종료. 사용자당 미종료 세션 하나 |
| 성장 | `reward_transactions`: 세션 적립과 아이템 지출의 원장. `items` → `user_inventory`: 보유 및 배치 여부. 레벨과 초기 업적은 읽을 때 계산 |
| 방 배치 | `user_room_layouts` → `room_item_positions`: 배치 버전과 보유 아이템별 위치. 비공개 `room_item_bounds`가 이동 범위를 관리 |
| 그룹 | `study_groups` → `group_members`, `group_updates`, `group_contributions`. 멤버십과 그룹장 제약, Realtime 버전 신호, 세션별 공동 목표 기여 |
| 챌린지 | `study_groups` → `study_challenges`. 공동 목표, 날짜·시간대, 서버가 계산한 기간 경계, 생성·취소 시각 |
| 공지 | `study_groups` → `group_notices`. 제목·본문, 작성·수정 시각, 동시 수정 검사용 버전 |
| 채팅 | `study_groups` → `group_messages`, `group_chat_updates`. 사용자 소유 메시지와 내용 없는 실시간 변경 신호 |
| 공동 도서관 | `study_groups` → `group_library_books`, `group_library_layouts`. `group_library_imports`는 사용자별 개인 서재 연결 |

모든 공개 테이블에서 RLS를 활성화한다. `authenticated`에 필요한 조회 권한만 명시적으로 부여한다. 개인 자료는 자신의 행만 읽을 수 있고, 그룹 변경 신호는 그룹 멤버만 구독할 수 있다. 그룹장만 비공개 코드 조회와 목표 수정을 할 수 있다. 그룹장이 탈퇴하면 가입 순으로 권한을 이관하고, 마지막 멤버이면 그룹을 삭제한다.

공개 RPC는 invoker 래퍼다. 보호된 쓰기와 집계는 Data API에 노출하지 않는 `onmode_private` 스키마의 함수에서 처리한다. 해당 함수는 `auth.uid()`와 소유권·멤버십을 확인하고 빈 `search_path`를 사용한다. 세션 시작·일시정지·완료는 서버 시각으로만 정산한다. 보상과 구매는 동일 사용자 잠금으로 직렬화하며 세션 ID와 아이템 ID 원장 제약으로 중복 처리를 차단한다.

그룹에 참여 중인 상태에서 완료한 세션을 그룹에 기여분으로 저장한다. 탈퇴해도 그룹 합계는 유지되며, 개인 랭킹은 현재 멤버의 현재 가입 기간만 집계한다. 그룹원에게는 이름·역할·목표·집중 상태와 합계만 공개한다. 개인 세션의 활동명이나 기록은 공개하지 않는다.

계정 삭제는 일반 그룹 탈퇴와 달리 해당 사용자의 세션과 그룹 기여분도 제거한다. RPC는 본인의 활성 세션과 최근 비밀번호 인증을 확인하고, 사용자별 작업과 그룹 변경을 잠금으로 직렬화한다. 공유 그룹의 그룹장을 이관하거나 빈 그룹을 삭제한 뒤 `auth.users`를 삭제하며, 소유한 개인 기록과 로그인 세션은 외래키로 함께 삭제된다. 운영 백업과 서비스 감사 로그의 보관 정책은 별도 출시 준비 항목이다.

챌린지의 생성·취소는 그룹장만 실행할 수 있다. 회원에게 직접 쓰기 권한을 주지 않으며, RLS로 같은 그룹의 멤버에게만 조회를 허용한다. RPC가 활성 계정과 멤버·그룹장 권한을 다시 확인한다. 생성 요청 ID로 재시도를 중복 처리하지 않고, 개인·그룹 잠금 순서를 기존 삭제 절차와 맞춘다. 챌린지 집계는 `group_contributions`와 검증된 집중 세션으로 계산하므로 클라이언트가 진도나 보상을 입력할 수 없다. 기간 경계는 저장한 시간대 기준으로 서버에서 계산하고 종료일 다음 날 0시를 제외 경계로 사용한다. 변경 시 기존 `group_updates` 신호로 멤버 화면을 다시 조회한다.

공지 테이블은 RLS로 그룹 멤버에게만 조회를 허용하고 직접 쓰기는 차단한다. 쓰기 RPC는 활성 세션·그룹장 권한과 수정 버전을 검증한다. 생성 UUID 및 동일 내용 수정 재시도는 중복 처리하지 않는다. 조회는 `(created_at,id)` 커서와 그룹별 복합 인덱스를 사용해 같은 작성 시각에도 누락·중복 없이 페이지를 나눈다. 개인 작성자 ID를 저장하지 않는 그룹 공유 자료이며 그룹 삭제 시 함께 삭제한다. 그룹장이 탈퇴하거나 계정을 삭제해도 남은 그룹에서는 공지를 유지한다.

채팅 RPC는 활성 세션과 현재 멤버십을 확인하고 발신자·시각을 서버에서 정한다. 그룹·발신자별 인덱스로 커서 조회와 전송 제한을 처리한다. 사용자 프로필 잠금으로 그룹 간 동시 전송도 직렬화하며, 같은 메시지 ID의 재시도를 먼저 확인해 중복과 제한 오차를 막는다. 삭제는 발신자 본인 또는 현재 그룹장에게 허용하고 본문을 NULL로 바꾼다. 발신자 계정에는 삭제 전파 외래키를 사용해 계정 삭제 시 해당 메시지를 제거한다. 메시지와 변경 신호 테이블 모두 RLS를 적용하고 클라이언트 직접 쓰기는 차단한다.

방 배치는 기존 스냅숏·명령 API에 합쳐 읽고 저장한다. 공개 배치 테이블은 본인 조회만 RLS로 허용하고 직접 쓰기는 차단한다. 서버가 보유 여부, 이동 가능 아이템, 정수 좌표와 범위를 검사하고 현재 버전과 일치하는 변경만 한 번에 저장한다. 이미 같은 배치가 저장된 재시도는 버전을 올리지 않는다. 구매·보상은 변경하지 않으며, 숨긴 아이템의 위치는 유지하고 계정 삭제 시에는 배치도 함께 삭제한다.

`activities.isbn`은 선택 필드이며, 책에만 정규화된 ISBN-13을 허용한다. DB가 길이·접두사·확인 숫자를 다시 검사하고 `(user_id,isbn)` 부분 유니크 인덱스로 동시 등록도 막는다. ISBN-10 변환은 순수 도메인 규칙에서 수행하며 RPC에는 정규화된 13자리를 보낸다. 기존 사용자 잠금과 개인 활동 RLS·조회 전용 권한을 유지한다. 다른 사용자는 같은 ISBN을 자신의 서재에 등록할 수 있지만 타인의 제목·독서 기록은 읽을 수 없다. ISBN이 없던 기존 도서는 그대로 읽고 쓰며, 공개 스냅숏·명령 래퍼의 방 배치 처리도 유지한다. 추가된 비공개 검증 함수의 클라이언트 실행 권한은 제거했다.

참고: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Data API 기본 노출 정책 변경](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically), [클라이언트 API 키](https://supabase.com/docs/guides/getting-started/api-keys).

공동 도서관의 공개 테이블은 RLS로 공동 목록·배치를 현재 멤버에게만, 개인 서재 연결은 본인에게만 조회 허용한다. 직접 쓰기는 차단하고 활성 Auth 세션을 확인하는 비공개 함수와 공개 invoker RPC로 처리한다. 사용자 프로필 → 그룹 순서로 잠가 탈퇴·계정 삭제·가져오기·배치를 직렬화한다. 공동 도서는 개인 자료에서 메타데이터만 복사해 원본 계정 삭제와 독립적으로 유지하며, 그룹별 ISBN 유니크 인덱스와 (created_at,id) 커서로 중복·페이지 경계를 처리한다. 공용 가구는 서버에서 정한 5종만 허용하고 정수 좌표·범위·배치 버전을 검사한다. 같은 배치 재시도는 버전을 올리지 않는다. 가져오기는 사용자별 연결 기본키와 기존 개인 ISBN을 조회해 중복을 방지한다. 그룹·공동 도서가 삭제되면 연결만 정리하고 개인 활동은 유지하며, 사용자 삭제 시 본인의 연결과 개인 활동을 함께 제거한다.
